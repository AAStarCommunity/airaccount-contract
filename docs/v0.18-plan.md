**Status:** proposed (for review). After sign-off → break into tasks → parallel-PR development → full test → internal Codex review → PR.
**Milestone:** [`v0.18`](https://github.com/AAStarCommunity/airaccount-contract/milestone) (15 issues assigned).

## Theme
Close the accepted-risk backlog (KI-4/KI-6 + the MEDIUM/LOW security findings), optimize gas, and finish the on-chain E2E coverage the beta.4 capability map flagged as "not yet exercised." One non-upgradable redeploy at the end (new impl/factory/guard/validator as needed).

## Parallel-PR workstreams
Each workstream = one PR, developed independently. Dependency notes below drive ordering.

### WS-A — Signature replay / binding hardening 🔴 (security) — highest blast radius
- **#75 (MEDIUM)** installModule/uninstallModule: add a per-(account,typeId,module) nonce so guardian sigs can't be replayed after a reinstall.
- **#84 (security)** add contract version/epoch to ALL guardian-signed hash domains (recovery, module, tier-change, force-exit) → cross-version/contract replay protection.
- **#45 (security)** BLS/DVT co-sign not cryptographically bound to the UserOp → replayable. Bind the BLS message-point to `userOpHash` (+ version/chainId/account) so a co-sign can't be lifted onto another op.
- **Approach:** ONE shared signed-data domain (version + chainId + account + nonce + userOpHash where applicable) applied consistently across guardian hashes (recovery/module/tier/force-exit) AND the BLS binding — so #75/#84/#45 are coherent, not ad-hoc per path. Touches `AAStarAirAccountBase`, `AAStarAirAccountV7`, BLS validation. **Do a unified design pass first.**
- **Acceptance:** replay-after-reinstall reverts; cross-version hash mismatch; a BLS co-sign for op A rejected on op B; existing guardian/BLS flows pass.

### WS-B — ForceExit TOCTOU 🔴 (security)
- **#70 (MEDIUM)** `executeForceExit`: re-verify the approving guardians are STILL current guardians at execution time (not just at approval), mirroring the beta.2 stale-guardian fix on the approval path.
- **Approach:** `ForceExitModule` re-reads guardians at execute, intersect with the approval set. Isolated to the module.
- **Acceptance:** test that a rotated-out guardian's approval no longer counts at execute time.

### WS-C — Session-key hardening 🔴 (security, `SessionKeyValidator`)
- **#83 (security)** cap session-key count per account (prevent unbounded registration / storage griefing).
- **#57 (KI-4)** velocity fixed-window 2× burst at boundary → sliding window or carry-over.
- **Acceptance:** count-cap revert test; velocity boundary test proving no 2× burst.

### WS-D — Module install timelock 🟡 (security, KI-6)
- **#58** optional timelock for module install at the default threshold (70).
- **Acceptance:** install-at-default-threshold enforces timelock; higher threshold (owner+2 guardians) can bypass.

### WS-E — Gas optimizations 🟡 (LAST among contract changes — re-packs final layout)
- **#82** TokenConfig 3→2 slots (uint128 tier fields); **#80** SessionState 2→1 slot (uint128 velocity); **#81** executeBatch guard-address SLOAD cache; **#79** `_popcount` assembly Hamming weight.
- **Dependency:** #82/#80 are STORAGE-LAYOUT changes; WS-A/C/D also add storage. **WS-E must land after the storage-adding WSs** so it packs the final layout (else layout churn / conflicts).
- **Acceptance:** `forge snapshot` gas deltas recorded; storage-layout test; EIP-170 still under limit.

### WS-F — E2E completeness 🟢 (test-only, fully parallel)
- **#90** real on-chain coverage for: session-key USE (scope/selector/velocity enforcement), completed social recovery (`executeRecovery` → owner change after timelock), EIP-7702 delegate→initialize→transact flow, `cancelRecovery` owner-rejection, guard-enabled tier rejection THROUGH a bundler, `proposeAlgorithm` timelock.
- **Acceptance:** new `scripts/e2e-*` phases; the beta.4 capability-map "not yet exercised" footnote shrinks to zero.

### WS-G — LOW fixes + docs 🔵 (mostly parallel)
- **#78** confirm EIP-7212 precompile canonical (low-S) — verify + document; **#77** ForceExit `_readGuardians` silent failure → explicit revert; **#76** ERC-1271 EIP-191 NatSpec; **#74** Factory/Guard `require(string)` → custom errors.

```
Parallel from day 1:  WS-A, WS-B, WS-C, WS-D, WS-F (tests), WS-G (LOW/docs)
Gate:                 WS-E (gas/storage-packing) starts AFTER WS-A/C/D merge (final storage layout)
```
