# v0.20.0 — Transaction Record Archive

Release validation transaction records. The flows below are exercised end-to-end with **real
secp256r1 cryptography** — `address(0x100)` is etched with OpenZeppelin `P256.verifySolidity`
(genuine curve math, no mock) and signatures are real ES256 WebAuthn assertions produced by a
software P-256 authenticator (`test/webauthn/gen_p256_assertion.mjs`, Node WebCrypto) over the
exact challenge the contract derives. Format is byte-for-byte what `navigator.credentials.get()`
returns on Apple/Google passkeys; only key custody differs (software vs Secure Enclave).

Source: `test/P256WebAuthnRealSig.t.sol` (run with `forge test --ffi`). Gas includes test-harness
deployment for the registration/removal cases (noted inline).

## Flows

### 1. Full passkey-only social recovery (2-of-2) — `test_fullPasskeyRecovery_realSignatures`
Gas: **682,273** (full cycle)

| # | Tx | Actor | On-chain effect |
|---|---|---|---|
| 1 | `proposeRecoveryWithSig(newOwner, 0, sig0)` | relayer (passkey#0 assertion) | opens proposal, auto-approves slot 0 (`approvalBitmap=0b001`) |
| 2 | `approveRecoveryWithSig(1, sig1)` | relayer (passkey#1 assertion) | adds slot 1 (`approvalBitmap=0b011`) → 2-of-2 threshold met |
| 3 | `warp(+2 days)` then `executeRecovery()` | anyone | timelock elapsed → `owner := newOwner`, `_recoveryNonce++` |

Verified: `account.owner()` actually changes to `newOwner` via real passkey signatures.

### 2. Passkey guardian registration + real proposal — `test_registerPasskeyGuardian_thenRealPropose`
Gas: **9,379,762** (incl. account deploy)

| # | Tx | On-chain effect |
|---|---|---|
| 1 | `addP256Guardian(PK1_X, PK1_Y)` (owner) | registers passkey#1 at the next slot (bootstrap) |
| 2 | `proposeRecoveryWithSig(newOwner, 1, realSig)` | the freshly registered passkey opens a recovery proposal |

### 3. Guardian removal — slot/key binding (#120 final-review HIGH)
- `test_removeMixedSigs_realSig_correctSlotSucceeds` — gas **9,301,692**: real P-256 (slot 0) + real
  ECDSA (slot 2) sigs authorized for slot 1 successfully remove slot 1.
- `test_removeMixedSigs_realSig_crossSlotRejected` — gas **9,327,212**: the SAME sigs submitted to
  remove slot 0 are **rejected** by the real verifier (rebuilt challenge differs). Confirmed to FAIL
  when the fix is reverted (attack succeeds without it) — proves the binding is real.

### 4. Negative controls (real verifier rejects forgeries)
- `test_realVerifier_rejectsWrongChallengeSignature` — gas **325,028**: a real sig bound to a
  different challenge (different newOwner) is rejected.
- `test_realVerifier_rejectsWrongKey` — gas **326,209**: a real sig from a non-registered key is rejected.
